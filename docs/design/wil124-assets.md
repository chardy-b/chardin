## Provenance record schema

Record beside each generated/exported asset (or beside the generator for code-created content): `id`, repository path, kind, creator/contributor identity, creation date, source (`original` plus generator/source path), generation command and dependency versions, input parameters/seed, modifications, byte length and SHA-256 when a file exists, license identifier or explicit rights status, rights-holder/permission evidence location, permitted repository distribution/product use, required attribution and notice location, reviewer/date and decision. Do not invent a human creator identity: agent-assisted work must say so and name the commissioning project, with ownership to be confirmed by its owner.

For procedural-only output, hash the reviewed generator/definition source and record canonical geometry counts/bounds; do not invent binary-file hashes. If files are exported, regeneration must reproduce byte hashes or document exactly which exporter metadata varies and compare canonical geometry/material content. Add all new distributed assets and baselines to `docs/asset-inventory.json` using its existing schema; keep richer metadata adjacent and extend its coverage test if a new distributed directory is introduced. Preserve old records until the owner resolves them; do not mark old assets cleared merely because new work is original.

Acceptance rule: missing source, unclear license, missing permission or required attribution blocks importing third-party content. `original; repository license pending` is an honest status for project-authored work during implementation, **not** permission for public redistribution. A package's MIT/Zlib license does not license original project art or inherited thumbnails. Owner confirmation of original-work rights and the repository distribution license is required before release. All URLs, if future exports need them, must be fixed same-origin paths under an allowlisted asset directory with bounded fetch/decode and dimensions; reject protocol-relative, cross-origin, backslash, control-character and executable URLs. Do not expose arbitrary URLs via test hooks or user input.
