## Deterministic interface

The existing `NEXT_PUBLIC_E2E_HOOKS=true` build guard controls API installation; mutating simulation controls additionally require `?e2e=1`. Ordinary production builds must keep the flag false. `step(frames,intent)` and `stepInput(frames)` retain frames at 60 Hz, integer bounds 0–3600 and running/manual guards. Rendering, warmup, resize and quality changes never advance the score. `setSkyTick(tick)` rejects nonintegers/nonfinite values and values outside 0–10800 before mutation, freezes playback and clears input. Invalid-score mode remains neutral even under this hook.

Snapshots add copied `generation`, `forward`, `supportId`, `supportUp`, `localFeet`, `cameraPosition`, `cameraTarget`, `cameraMode`, `travelerVisible` (the actual scene owner), `landmarkAvailable`, `sky` (tick/phase/playback) and `route` (world-space P0–P4). No live vectors, meshes, materials or resource owners are exposed. There is no teleport hook. `tests/e2e/helpers/skyspace-route.ts` navigates these waypoints using the real motor through bounded manual steps; CPU runtime tests exercise that same helper. `?e2e=1&landmarkFailure=1` and `scoreFailure=1` inject local failures only in the explicitly enabled deterministic mode. They are ignored in ordinary production.
