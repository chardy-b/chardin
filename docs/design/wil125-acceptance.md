# WIL-125 implementation and acceptance handoff

## Implementation order

Read [the design](wil124-skyspace.md) and [asset contract](wil124-assets.md). WIL-124 is a design handoff; all tests below are **required future work**, not claimed results. The user’s 2026-09-08 blanket approval is the design approval. Independent review, Wave 1 gate disposition and eventual implementation/release evidence remain distinct.

1. Add validated Landmark data, pure geometry/ramp generation and collider queries. Prove dimensions, frame determinant, capsule clearance and joins before art detail. Keep existing no-collider motor tests as compatibility evidence.
2. Wire support state and collision into motor/Traveler/camera. Verify round-trip entry, running, jumping, corner sliding and both camera sweeps. Add the score reducer and deterministic hooks against integer ticks.
3. Compose through the existing runtime/resource scope and readiness generation; wire semantic commands/status, still alternative and failure behavior through the existing Experience adapter. Add no server route, API, network asset or renderer.
4. Tune original radiance/materials within the specified endpoints; capture and review normal/Low/HDR-fallback images before accepting baselines. Measure full-scene budgets and record unresolved devices truthfully. Tune beyond the stated geometry/score parameters only with a documented design amendment.
5. Execute validation and independent review on the final implementation source. Repair findings, refresh affected evidence and obtain review of the repaired diff. The parent handles future PR/CI publication under its separate authorization; never infer deployment approval.

## Release data and approval boundaries

WIL-125 can use this design without rediscovering architecture. The following data must still be supplied by the controller/owner before declaring Wave 2 released: accepted Wave 1 gate disposition; reviewed whole-frame/startup/bundle numeric budgets and strict runs; representative physical desktop/mobile including thermal/startup and Safari/iOS evidence; exact-source terminal CI/security checks including CodeQL; independent final-diff spec/security/quality/originality review; original-work distribution license and inherited thumbnail/template/favicon rights decisions. See the [existing release ledger](../release-readiness.md) for earlier results, not automatic passes.

The 2026-09-08 blanket user approval fulfills **design approval**. It does not erase those evidence dependencies. No further design choice is intentionally left to release hardware data: structural geometry, route, collision/camera behavior, light semantics, silent audio, fallback and accessibility behavior are fixed above. Performance tuning that changes them needs a documented amendment. PR publication, merging, Vercel and DNS remain outside this WIL-124 execution.
