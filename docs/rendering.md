# Rendering ownership and profiles

WIL-122 uses Three.js 0.185.1 and postprocessing 6.39.4, whose declared Three peer range is `>=0.168.0 <0.186.0`. The dependency is lockfile pinned. No Messenger code, shaders, or assets were copied. The four-band diffuse ramp, four-neighbour depth/normal crease detector, scene palette, and composition are authored for Chardin. SMAA lookup data ships with postprocessing under that dependency's license. This does not grant a repository-wide redistribution license.

The runtime owns one renderer, frame loop, and resize observer. The composer executes scene rendering, a geometry normal pass, the original outline effect, optional bloom, ACES tone mapping, and optional SMAA. Intermediate buffers remain linear. The renderer uses `NoToneMapping`; `ToneMappingEffect` maps tone once and the final screen pass encodes sRGB once. Half-float targets require `EXT_color_buffer_float`, otherwise unsigned-byte targets are used.

| Profile  | DPR cap | Target scale | Terrain / grass    | Shadow map | Effects               |
| -------- | ------- | ------------ | ------------------ | ---------- | --------------------- |
| High     | 2       | 1            | high / 1,520 tufts | 1,024²     | outlines, bloom, SMAA |
| Balanced | 1.5     | 0.85         | medium / 960 tufts | 512²       | outlines, bloom, SMAA |
| Low      | 1       | 0.7          | low / 520 tufts    | 256²       | outlines              |

The effective drawing ratio is capped DPR multiplied by target scale. Tone mapping and both outline signals remain enabled on every tier. Reduced motion disables bloom on all tiers. Unknown capabilities, coarse pointers, or limited CPU/memory start at Low; capable fine-pointer devices start at Balanced. High requires explicit selection. Bounded windows of 120 valid frame samples can downgrade one tier when at least 90 frames exceed the tier threshold (22 ms at High, 34 ms at Balanced). Pauses and stalls above 250 ms do not count as performance evidence. There is no automatic upgrade.

All three bounded terrain/grass pairs are prepared and uploaded during loading, using the selected tier's DPR, shadow resolution and effect settings throughout warmup. The drawing buffer is bounded before composer construction; Low startup never allocates High render targets. Geometry upload still covers all bounded content variants, so total startup CPU/GPU work needs physical-device measurement. Transitions reuse scene content and passes, resize targets, and replace the shadow map when necessary. The motor continues using its original radius of 5.03; visual level of detail does not alter collision geometry. Repeated terrain queries reuse a prebuilt sampler. Its contract remains immutable, centered, convex, non-indexed geometry with translation-only mesh convenience queries; it is not a future pavilion collider.

Every successful runtime allocation is registered for reverse-order cleanup. Runtime readiness waits for the traveler load/fallback and embedded SMAA images, then warms the render paths. The traveler has an eight-second deadline across fetch, body decoding and parsing: timeout aborts the request and resolves readiness to the existing primitive fallback even if the transport ignores abort. Late assets are disposed rather than attached; successful completion or disposal cancels the deadline. Context loss disposes the old runtime; restoration creates a fresh generation and waits for an explicit Resume gesture. Retry while graphics are still lost preserves the recovery state and restoration listener; it never constructs against a lost context or silently starts a new runtime. Stale asynchronous completions cannot change the current lifecycle. Frame, resize, preference, and initialization failures enter the safe HTML failure state. Reduced-motion updates still select Idle after walking or landing, immediately applying its initial pose with zero animation-time advancement instead of freezing a previous locomotion pose.

The test API exposes copied state and deterministic controls only in explicitly enabled builds. The browser fixture retains the context-loss extension before inducing loss, because querying extensions while lost can return null. Tablet capture waits for the runtime's successfully rendered viewport, then finishes outstanding GPU work before screenshot comparison. GPU synchronization is confined to the test fixture and is not used in the running experience.

The Linux VM/SwiftShader and emulated Pixel 5 results establish functional rendering evidence only. Representative desktop/mobile frame budgets, physical mobile startup timing, and Safari/iOS remain unverified release requirements. Existing legacy asset-provenance and repository-license decisions remain with the project owner.

WIL-123 adds a separate bounded browser probe for submitted draw calls/triangles and logical texture storage, plus RAF and synchronized frame-service timing. See [performance methodology](performance.md) for units, limits, missing results and required budget review. No measurement instrumentation is imported into the runtime.
